# 설문 집계기 구현 계획서

근거: [설계서](설계서.md) (승인됨, 2026-11-17)

## 파일 구성

| 파일 | 내용 |
|---|---|
| `index.html` | 앱 전체. 계산 로직은 `id="tally-logic"` 스크립트 블록에 두고, 화면 코드는 다른 스크립트 블록에 둔다 |
| `tests/tally.test.mjs` | `index.html`에서 계산 블록만 읽어 시험한다. `node --test tests/`로 돌린다 |
| `.nojekyll` | 빈 파일. GitHub Pages가 Jekyll 처리를 건너뛰게 한다 |

## 작업 순서 (작업마다 커밋)

1. **계획서**: 이 문서를 쓴다.
2. **.nojekyll**: 저장소 맨 위에 빈 파일을 넣는다.
3. **계산 로직과 시험**
   - 칸 판정: 유효, 빈 응답, 제외로 나눈다(설계서 규칙 ①~③).
   - 붙여넣은 글 해석: 머리글, 첫 열 제외, 모자란 칸과 남는 칸, 빈 줄을 처리한다.
   - 평균: 정수 계산으로 소수 셋째 자리에서 반올림한다. 부동소수 오차 때문에 3.125가 3.12로 나오는 일을 막는다.
   - 시험: 사례 1~10, 그리고 문항마다 "유효 + 빈 응답 + 제외 = 전체 응답 수"가 맞는지 본다.
4. **화면**
   - 입력창, 비우기 버튼, 빈 입력일 때의 안내, 결과 표.
   - 입력이 바뀌면 바로 다시 집계한다.
   - 좁은 화면에서는 표 안에서만 가로로 밀고, 문항 열은 고정한다.
   - 데이터가 밖으로 나가지 않게 한다.
     - 콘텐츠 보안 정책으로 페이지가 어떤 외부 요청도 못 하게 막는다.
     - 저장소 API는 쓰지 않는다.
     - 입력창 자동 복원을 끈다(`autocomplete="off"`).
5. **확인**: 설계서의 성공 확인 기준을 하나씩 확인한다.
   - 시험 명령으로 계산을 확인하고, 로직을 일부러 틀리게 바꾸면 시험이 실패하는지도 본다.
   - 헤드리스 브라우저로 화면, 네트워크 요청, 저장소를 확인하고, 폭 360px 화면을 본다.
   - 사람이 직접 봐야 하는 항목(실제 휴대폰에서 붙여넣기, 비행기 모드)은 확인하지 못한 것으로 따로 적는다.
6. **PR**: 시험이 통과하면 PR을 연다. PR 본문에 확인 결과를 적는다.
